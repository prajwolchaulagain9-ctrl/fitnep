# FitNEP

College project: a nutrition and fitness app for Android and iOS.

## Setup

Use Flutter with Dart 3.13.4 or a compatible later 3.x SDK.

```powershell
flutter pub get
flutter devices
flutter run -d <device-id>
```

The notifications frontend reads its API root from a Dart define:

```powershell
flutter run -d <device-id> --dart-define=API_BASE_URL=https://api.example.com/
```

Notification requests use the stored bearer token:

- `GET /notifications`
- `PATCH /notifications/{notificationId}/read`
- `PATCH /notifications/read-all`

The backend must derive the user from the token and scope reads and updates to
that user. No recipient/user ID is sent by the mobile client.

Firebase Cloud Functions backend scaffolding is available in `functions/`. It
verifies Firebase ID tokens and enforces recipient-scoped notification APIs.
Notifications persist in Firestore, while direct mobile Firestore access is
denied. Backend-owned triggers generate notifications for diet plans, messages,
tasks, and successful payments without duplicates. See `functions/README.md`
for the schema, emulator tests, and deployment steps.

Choose an Android phone/emulator or an iOS device/simulator.
iOS builds require macOS and Xcode.

currently unused.

## Main dependencies

- `flutter_riverpod`: app state and dependency injection.
- `go_router`: navigation.
- `dio`: backend HTTP requests.
- `flutter_secure_storage`: token storage.
- `intl`: date, number, and price formatting.

Feature-specific packages can be added as the mobile app grows.

## Configuration and assets

`.env.example` and `config/development.example.json` are future configuration
templates. No configuration loader has been implemented.
Never put backend private keys or passwords in a mobile app.
Local `.env` and `config/development.json` are ignored by Git.

Asset declarations in `pubspec.yaml` remain commented until real files are added.
Declare custom font families after adding the font files.

## Git

Build files, IDE files, local configuration, and signing keys are ignored.
Keep example configuration and `pubspec.lock` in version control.

Nothing has been committed or pushed. Review and push the initialization
changes yourself when ready.
